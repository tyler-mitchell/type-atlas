project overview

Agent semantic
intelligence layer

A language-server-backed MCP server that gives code agents the same semantic understanding of a codebase that a human developer has in their editor — types, diagnostics, hover information, references, and code actions — without requiring per-library plugins or editor infrastructure.

01 — problem

The feedback gap

Human developers receive continuous, ambient semantic feedback while editing. Type errors appear inline. Hover reveals inferred types and documentation. Go-to-definition traces through generated and imported types. This signal is passive, zero-cost, and spatially attached to the code.

Code agents operate in a polling model. They write files, then explicitly invoke tools to discover what went wrong. The feedback loop is coarser, later, and requires the agent to correlate diagnostic output back to decisions it made — consuming inference time and context window on the correlation step rather than the fix.

human model
Subscription — signal arrives passively
Diagnostics, types, and hover information update continuously as the developer types. Zero explicit cost per signal.
agent model (current)
Polling — agent must ask explicitly
Agent writes a file, invokes tsc or a lint script, parses stdout. Each check has cold-start cost. Signal is delayed and structurally disconnected from the code that caused it.
missing capability
No baseline disambiguation
Agents cannot distinguish errors they introduced from pre-existing technical debt without manually snapshotting state before and after — which no current tooling does automatically.
missing capability
No speculative analysis
Agents cannot ask "what would break if I make this change" without actually making the change. Editors can simulate edits against in-memory documents. Agents write to disk and discover consequences reactively.
02 — architecture

Stack

A thin MCP server acts as an LSP client, translating agent tool calls into LSP requests directed at a Volar language server. Volar handles document sync, TypeScript integration, and the full language intelligence surface. The agent never speaks to the language server directly.

consumer
Codex / Claude Code agent
Issues MCP tool calls. Reads structured diagnostic snapshots and semantic query results back into context window.
mcp layer
MCP server — LSP adapter
Thin bridge. Translates tool calls into LSP requests. Formats LSP responses into agent-readable diagnostic markup. Manages baseline snapshot diffing. No language intelligence of its own.
language server
Volar language server
Handles document sync lifecycle, TypeScript integration via tsserver, virtual document composition for framework file formats, incremental diagnostics, and the full LSP capability surface.
compiler
tsserver / TypeScript compiler API
ts.createSemanticDiagnosticsBuilderProgram. Incremental recheck on file change. Resolves node_modules .d.ts files, project references, path aliases, and generated type artifacts.
filesystem
Project files + node_modules + generated types
Source .ts/.tsx files. All imported library .d.ts files resolved automatically — no per-library configuration. routeTree.gen.ts kept fresh by a watcher started at session boot via Codex hooks.
03 — tool surface

Agent tool API

Tools are designed around agent access patterns — file-oriented and range-based rather than cursor-relative. The cost ladder principle from cx applies: start with the cheapest query that answers the question, escalate only when needed.

tool
description
cost
get_diagnostics(file?)
Returns current error and warning state. Scoped to a file or full project. Includes baseline/new scope tags, causal chains, and available fixes. Reads from daemon cache — near-zero latency.
low
get_type_at(file, line, col)
Returns the inferred type and JSDoc at a position. Hover equivalent. Resolves through generics, declaration merging, and imported library types including full .d.ts chains.
low
get_signature(file, line, col)
Returns the active overload signature, parameter names, types, and documentation at a function call site. Prevents import and parameter misuse before a write.
low
get_code_actions(file, line, col)
Returns compiler-known repairs at a diagnostic location — add import, narrow type, implement interface members. Deterministic fixes the agent can apply without synthesizing a solution.
mid
get_definition(file, line, col)
Resolves a symbol to its declaration site. Follows through re-exports, type aliases, declaration merging, and generated types — not just naive file search.
mid
get_references(file, line, col)
Returns all usage sites of a symbol across the project. Type-aware — not regex. The pre-flight check for any rename or signature change.
mid
get_enriched_file(file)
Returns source with diagnostic annotations and inferred types woven inline. The closest analog to the human's annotated editor view. Highest token cost, highest information density.
high
snapshot_baseline()
Records current diagnostic state as the baseline. Subsequent get_diagnostics calls tag new errors as scope=new and pre-existing errors as scope=baseline. Enables clean disambiguation.
low
04 — diagnostic format

Snapshot markup

Structured XML-like format optimized for agent consumption. Token-efficient while preserving causal chains, scope disambiguation, and fix options. The scope attribute is the most important field — it tells the agent which errors it introduced versus which were pre-existing.

<diagnostic-snapshot session="s_4f2a" baseline-errors="3" new-errors="2"> <error id="e1" scope="new" file="routes/user/$id.tsx" line="23" code="TS2345" fixable="true"> <message>Argument of type 'string | undefined' is not assignable to parameter of type 'string'</message> <chain> <because>params.id typed as string | undefined by RouteParams<'/user/$id'></because> <because>getUser() requires string — undefined not accepted</because> </chain> <fix type="narrowing">if (!params.id) return notFound()</fix> <fix type="assertion">params.id! — only if id guaranteed by route</fix> </error> <error id="e2" scope="new" file="routes/user/$id.tsx" line="31" code="TS2339" fixable="false" related="e1"> <message>Property 'profile' does not exist on type 'UserData | null'</message> <note>Likely resolves if e1 is fixed — downstream of same null</note> </error> <warning id="w1" scope="baseline" file="components/Avatar.tsx" line="8" code="TS2532"> <message>Object is possibly undefined</message> <note>Pre-existing — do not fix in this task</note> </warning> </diagnostic-snapshot>
05 — agent integration

Lifecycle via Codex hooks

The language server is started and stopped via hooks.json at session boundaries. The baseline snapshot is taken automatically at SessionStart so every subsequent diagnostic call has scope disambiguation without the agent having to think about it. The route tree watcher is also started here to keep generated types fresh.

// .codex/hooks.json { "hooks": { "SessionStart": [{ "hooks": [{ "type": "command", "command": "node .codex/hooks/session-start.js", "statusMessage": "Starting language intelligence...", "timeout": 20 }] }], "Stop": [{ "hooks": [{ "type": "command", "command": "node .codex/hooks/session-stop.js", "timeout": 10 }] }] } } // session-start.js — starts MCP server, warms Volar, snapshots baseline await startMcpServer(); // spawns Volar language server await startRouteTreeWatcher(); // keeps routeTree.gen.ts fresh await snapshotBaseline(); // records pre-existing error state
